# QEX and Grid reductions and tensor contractions

Research date: 2026-09-12. Status: primary-source evidence and design implications for the reopened Milestone 1. This report does not accept a reduction syntax or promise native support for every combination.

## Sources and limits

The inspected local checkouts are QEX [`6d3464c14be2285438aa69eee2026c9077b087cc`](https://github.com/jcosborn/qex/tree/6d3464c14be2285438aa69eee2026c9077b087cc), from `jcosborn/qex`, and Grid-HISQ [`7e702e5db0c8004a274d752bf79ff5aa26cc0b89`](https://github.com/ctpeterson/Grid-HISQ/tree/7e702e5db0c8004a274d752bf79ff5aa26cc0b89), from `ctpeterson/Grid-HISQ`. Grid has an existing local `configure.ac` modification; the cited reduction and tensor files are unmodified. QEX's checkout is clean. The source files below were inspected locally. Browser retrieval of these exact pinned files failed; Grid's [official lattice API documentation](https://paboyle.github.io/Grid/docs/API/lattice_containers.html) independently confirms the distinction between global reductions, site-local contractions, outer products, and slices. The source snapshots govern details that the older API documentation does not cover.

This is source research, not GPU or multi-rank numerical validation. Negative availability findings mean no general API was found in the inspected source, not that no specialized implementation could exist elsewhere.

## The three operations to keep distinct

1. **Pointwise contraction:** reduce a site's tensor indices while retaining every lattice site. A matrix-valued Field's trace is a Numeric-valued Field on the same Lattice. A norm or inner product similarly contracts internal components. No rank collective is implied.
2. **Rank-local lattice reduction:** combine all scalar sites owned by one rank, including all relevant SIMD lanes, into one unpacked value. Summing a tensor-valued Field can return a tensor; summation need not contract its internal indices.
3. **Global lattice reduction:** combine rank-local results over the Lattice communicator, returning the result to every participating rank.

Grid exposes this separation directly as `localNorm2` / `localInnerProduct`, `rankSum`, and `sum`. Its documented global result is identical across the relevant communicator. QEX's traditional `norm2(Field)`, `dot(Field, Field)`, `sum(Field)`, and even `trace(Field)` are global reductions. Therefore Quark cannot translate the spelling `trace(field)` directly to QEX's identically named Field overload if Quark means a pointwise Field result. Use QEX's site operation through its native iteration/expression facilities. [Grid local operations](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_local.h#L41-L84), [Grid rank/global sum](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L161-L177), [QEX Field operations](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/field/fieldET.nim#L643-L801).

## QEX reduction machinery

The ordinary Field reduction path iterates the Field or its subset, accumulates a packed value, calls `simdSum`, and invokes `f.l.threadRankSum`. The Layout forwards that last operation to its own communicator. `threadRankSum1x` combines threads, calls the rank reduction on thread zero, and broadcasts the answer back to the threads. QEX's reduction test calls Field norms collectively within a `threads` region. The adapter must respect this participation pattern rather than put the collective into an arbitrarily chosen worker's site body. [Field reductions](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/field/fieldET.nim#L643-L801), [Layout forwarding](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/layout/layoutX.nim#L351-L352), [thread/rank combination](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/comms/commsUtils.nim#L195-L205), [native test](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/tests/base/treduce.nim).

Accelerator reductions have an explicit `GpuSum[T]` facility: allocate with `newGpuSum[T]`, accumulate a value per worker inside `onGpu`, invoke `gs.reduce` collectively, and obtain `gs.value` after completion. CUDA's implementation performs block sums, records partial results, and lets the final block combine them. It is addition-specific, not an arbitrary user-defined combiner. An existing halo example reduces six observables together through `GpuSum[array[6,float]]`, with SIMD folding performed before `gs.reduce`. The primitive itself does not perform a rank collective; global reduction requires a separate native communicator operation. A CPU implementation of the same interface uses QEX's thread sum. [CUDA implementation and example](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/backend/cudasum.nim#L100-L144), [six-observable use](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/comms/halogpu.nim#L247-L276), [CPU implementation](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/backend/cpu.nim#L135-L147).

QEX provides thread maximum operations and communicator `max` / `min` for `float64`. The older `threadRankMax` path calls `qmpMax` through `rankMax`, rather than taking the Field's communicator as the Field sum path does. These facilities are useful evidence for host maxima, but they are not evidence of a general, context-preserving GPU max/min reduction. [Thread maximum](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/base/threading.nim#L397-L424), [rank maximum](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/comms/commsUtils.nim#L277-L317), [communicator operations](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/comms/comms.nim#L52-L64).

## Grid reduction machinery and placement

`sum_cpu(pointer, outerSites)` partitions work among native host threads, accumulates packed objects, applies `Reduce` to fold SIMD lanes, and combines the thread results. CUDA/HIP `sum_gpu` uses Grid's own device reduction machinery and copies the final result to the host after synchronization. SYCL uses `sycl::reduction`. These are existing backend facilities for the adapter to call, not algorithms for Quark to duplicate. [Host sum](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L41-L102), [CUDA/HIP sum](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction_gpu.h#L203-L239), [SYCL sum](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction_sycl.h#L8-L29).

Grid's ordinary `rankSum(Field)` chooses CPU versus accelerator from build flags and opens the corresponding view internally. On a GPU-enabled build this would violate an explicit Quark `within Host` if called blindly. The Host adapter path must select the native CPU primitive with CPU access; the Accelerator path must select the accelerator primitive. `rankInnerProduct` similarly opens AcceleratorRead views and launches `accelerator_for`. Placement is therefore a real reduction contract, even though the native convenience APIs hide it. [Dispatch](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L132-L177), [inner product](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L254-L338).

Global sum and maximum reuse the Grid communicator. Depending on configuration, floating sums call MPI Allreduce or Grid's point-to-point reduction; maxima call MPI Allreduce with MPI_MAX. Quark should specify the communicator and mathematical result without substituting a new collective algorithm or promising a common floating-point addition order across backends and configurations. [Communicator implementation](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/communicator/Communicator_mpi3.cc#L268-L325).

## What the native norm definitions actually mean

Both tensor implementations recursively sum squared magnitudes of matching numeric components. For a numeric-leaf vector and matrix this means

```text
norm2(v) = sum_i |v_i|² = v†v
norm2(M) = sum_i,j |M_ij|² = trace(M†M)
```

The matrix quantity is the squared Frobenius norm. It is not the square of the nuclear/trace norm, `(sum singularValues(M))²`. The backend source settles this without selecting a norm merely from naming convention. Nested vector/matrix tensors recurse through their components. QEX's complex norm explicitly adds real-part squared and imaginary-part squared; Grid's vector and matrix inner products recursively sum component inner products. [QEX complex norm](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/maths/complexConcept.nim#L270-L290), [QEX tensor norms](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/maths/matrixConcept.nim#L627-L672), [Grid tensor inner products](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/tensors/Tensor_inner.h#L270-L299).

Grid's `localNorm2(Field)` produces a Field of site self-inner-products; `norm2(Field)` returns the globally summed norm as `RealD`. For complex input, the local implementation's `tensor_reduced` self-inner-product retains a complex scalar leaf whose imaginary part is mathematically zero; the adapter must enforce Quark's chosen real-valued norm result explicitly. QEX's Field norm is also globally summed. [Grid pointwise norm](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_local.h#L41-L51), [Grid global norm](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L202-L224).

No general vector/matrix `normInf` or infinity-norm API was found by searching QEX `src` and Grid `Grid`, including the tensor implementations. Grid does have `maxLocalNorm2(Field)`, defined as

```text
max_x norm2(field[x])
```

It computes the pointwise self-inner-product Field, scans scalar sites on the host with `peekLocalSite`, then invokes GlobalMax. For vectors this is the maximum site Euclidean norm squared; for matrices it is the maximum site Frobenius norm squared. It does not select a maximum component or a maximum absolute row sum. Its square root is a possible Field supremum norm with the existing site norm, but that interpretation is a mathematical inference, not a native tensor `normInf` overload. This routine cannot silently satisfy Accelerator placement because its maximum scan is on the host. [Exact implementation](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L228-L252).

Consequently the common backends settle squared Euclidean/Frobenius semantics. They do not settle whether a requested tensor infinity norm should be maximum component magnitude, induced maximum absolute row sum, or another separately named quantity. That remaining choice belongs in the portable contract.

## Precision and correctness constraints exposed by the source

- QEX Field `norm2P` converts each site value to double before squaring and accumulating. `dotP` has a double accumulation type but evaluates the site `dot` in its operand types first. These are observably different precision policies. Ordinary Field `sumP` accumulates in the evaluated site type. [Source](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/field/fieldET.nim#L643-L795).
- Grid `sumD_cpu` returns a double scalar object, but its per-thread `vvsum` is still input `vobj`; promotion happens after that packed accumulation. CUDA/HIP `sumD_gpu` extracts lanes and promotes before addition. SYCL first calls `Reduce` on an input packed value and then converts the result to double. A double result type does not prove that every multiplication, lane fold, or accumulation happened in double. [CPU](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L73-L102), [CUDA/HIP](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction_gpu.h#L101-L141), [SYCL](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction_sycl.h#L8-L29).
- QEX `Comm.allReduce(SomeInteger)` converts through Nim `float`, then converts back. Large integer sums can therefore lose exactness even without integer overflow. Grid has native uint32/uint64 global sums. Integer reduction conformance must check the actual operation, not infer exactness from its argument type. [QEX conversion](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/comms/comms.nim#L52-L57), [Grid integer sums](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/communicator/Communicator_mpi3.cc#L291-L305).

Milestone 1 should distinguish site-expression precision, accumulation precision, and returned precision; define integer behavior, empty-domain identities, and max/min treatment of unordered values; and require explicit rejection when an adapter cannot preserve the contract. This does not require Quark to replace native reduction algorithms.

## Other tensor algebra

Both backends recursively trace matrix diagonal components, so a matrix of matrices can contract all matrix levels to a numeric leaf. Grid separately offers indexed partial traces. Trace on a vector is not the same scalar contraction and should not be required indiscriminately by a generic Tensor concept. [QEX trace](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/maths/matrixConcept.nim#L605-L617), [Grid trace](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/tensors/Tensor_trace.h#L39-L70), [Grid indexed operations](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/tensors/Tensor_index.h#L32-L95).

Grid's `outerProduct(v,w)` explicitly computes `v_i * conj(w_j)` recursively and also has a pointwise Field overload. QEX supplies adjoint wrappers and conjugating `dot(x,y) = adj(x)*y` at complex leaves; however, a general value-returning vector outer-product API was not found in the inspected `maths` modules, and the vector/vector-to-matrix multiplication registration is commented out. Do not infer conformance merely from the presence of adjoint and multiplication individually. [Grid outer product](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/tensors/Tensor_outer.h#L37-L67), [QEX adjoint](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/maths/types.nim#L209-L234), [QEX dot](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/maths/complexConcept.nim#L503-L506), [QEX multiplication registration](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/maths/matrixConcept.nim#L558-L566).

Determinant deserves stronger numerical conformance. Grid's generic matrix determinant permits only numeric-level coefficients and uses elimination without pivoting. A nonsingular matrix with a zero first pivot, such as the 2×2 swap matrix, therefore exposes a division-by-zero path by direct inspection. QEX has direct formulas for dimensions 1–3, then a pivoting general routine whose singular-pivot handling is commented out. These are concrete test cases to add, not reasons to weaken determinant semantics. A determinant of nested spin/colour blocks additionally requires an explicit full-matrix interpretation or a stated unsupported domain; neither implementation establishes a general block determinant by recursively applying scalar formulas. [Grid determinant](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/tensors/Tensor_determinant.h#L48-L68), [QEX determinant](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/maths/matrixFunctions.nim#L14-L77).

Adjoint, conjugation, transpose, and a conjugating inner product are useful accompanying contracts: they specify the operations needed to state `v†w`, `vw†`, and `trace(M†M)` unambiguously. The precise supported shapes and promotion rules should be checked through small capabilities and operand-pair conformance.

## Fusion, slices, and implications for syntax

QEX's accelerator example accumulates multiple mapped observables before a single `GpuSum` call. Grid has dedicated fused operations such as `axpby_norm_fast` and paired inner-product/norm accumulation. However, Grid's ordinary `sum(expression)` first calls `closure(expression)`, and closure constructs a Lattice; expression syntax alone is not a guarantee of fused map-reduce. Its rank inner product also allocates a site-sized temporary buffer. A Quark expression/body interface can expose the opportunity while delegating to native operations; a no-temporary guarantee would be an additional backend requirement requiring evidence. [Grid fused helpers](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L341-L448), [Grid closure](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_ET.h#L488-L513).

Slice sums are established lattice work. Grid's `sliceSum(field, direction)` returns one value per global coordinate of the retained direction, combining SIMD and ranks. QEX has an observable-specific `norm2slice` that bins scalar sites and then performs `threadRankSum` on the sequence. These support reserving a future slice/grouped-reduction extension without forcing it into the first syntax decision. [Grid slice sum](https://github.com/ctpeterson/Grid-HISQ/blob/7e702e5db0c8004a274d752bf79ff5aa26cc0b89/Grid/lattice/Lattice_reduction.h#L455-L537), [QEX slice norm](https://github.com/jcosborn/qex/blob/6d3464c14be2285438aa69eee2026c9077b087cc/src/observables/sources.nim#L9-L18).

The source supports the following design constraints, independently of spelling:

- A lattice reduction belongs inside `within Host` or `within Accelerator`, with explicit site granularity and readable scoped views where a site body is used.
- A complete reduction owns its native parallel execution and combination. It should not be an unsynchronized update of an ordinary outer variable in a `parallel` loop.
- Packed iteration folds the selected packing lanes exactly once, without confusing them with tensor component indices.
- Rank-local versus communicator-global scope must be specified. A global operation is collective across the selected communicator and returns an ordinary owned result after completion.
- Site trace, determinant, norms, and inner products retain Field geometry when applied pointwise. A separately named lattice reduction performs the cross-site operation.
- Addition has the clearest native common path. Max/min, custom combiners, mixed tuple operators, empty selections, and precision policies need their own capability checks; a spelling that accepts them is not proof of implementation.
- Keep source selection, view lifetime, result shape, and placement portable; keep storage, synchronization, SIMD folding, native reductions, and communicator algorithms in the backend.
